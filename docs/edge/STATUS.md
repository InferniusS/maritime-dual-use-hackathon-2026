# PipeForge Edge implementation and verification

The verification below records the 3.1 baseline. Current engineering hardening, source-data upgrade behavior and remaining boundaries are documented in [V3_2.md](V3_2.md).

Edge extends the preserved v2 engineering engine and Three.js workspace. The baseline checkpoint and inspected risks are in [AUDIT.md](AUDIT.md). Engineering approval here means review of a computed proposal; it does not establish construction approval or regulatory certification.

| Capability | Implemented scope | Practical boundary |
| --- | --- | --- |
| Revisioned sessions | Drawing IDs, canonical SI model, stable object-to-CAD handle map, SQLite persistence and audit | Source synchronization depends on an explicit adapter and supplied engineering semantics |
| Incremental updates | Typed pipe/obstacle upsert and removal, optimistic revision checks, unchanged result reuse, nearby physical dependency invalidation | Conservative source-route bounds; optimization still inspects full physical context |
| Async jobs | Analysis/optimization tied to source revision, bounded work, cancellation and stale-result rejection | Jobs are process runtime state; completed session/proposal/audit data persist |
| Recommendations | Actual issue measurements, locations, object references, configured requirements and deterministic explanations | No language model produces geometry or certifies results |
| Designer review | Original/proposed geometry, independent validation, remaining UNVERIFIED checks, one explicit approve/reject decision, guarded export | A session-only application endpoint requires approval and explicit confirmation; no original DWG is written |
| Companion UI | Existing 3D viewer, issue selection, proposal preview, edit synchronization, optional live analysis, approval/export and audit inspection; attach a shared native session by ID or `?edge_session=...`; lightweight event/revision polling | Native sessions retain CAD ownership of source edits; external revisions require explicit source-view loading; UI audit download covers the latest 100 events |
| CAD exchange | Existing semantic JSON, strict DXF import/export, explicit supported source-unit conversion, actual entity handles, CSV/text instructions, optional STEP | Ordinary solids/centerlines do not establish system type, connectivity or catalog approval; unitless input needs an engineer declaration |
| Native AutoCAD adapter | C# project targeting regular AutoCAD 2025/2026 .NET 8, mapped geometry, event batching, async jobs, transient preview and explicit review/export | Exact workstation release unknown; Plant 3D semantics are unsupported; managed assemblies, compilation, NETLOAD and runtime behavior require Windows verification |
| Remote worker | Optional protocol-checked FastAPI CPU service, manual endpoint, health check, timeout, local fallback and local result verification | Actual Windows-to-IQ-9075 networking, ARM64 installation and physical performance remain unverified |
| GPU/NPU/AI | No acceleration required for deterministic routing and validation | No Qualcomm GPU/NPU execution or AI model inference is claimed |

All validation statuses retain `PASS`, `FAIL`, `UNVERIFIED` and `NOT_APPLICABLE`. Missing authoritative standards, approved commercial fittings, nozzle orientation and joint topology remain unverified after designer approval. Existing conservative geometry and hydraulic limits are described in [the v2 status](../IMPLEMENTATION_STATUS.md).

The **32 independent session/API tests passed** in this Linux instance. They check source immutability, atomic invalid deltas, revision conflicts, handle preservation, physical cache dependencies, full-analysis equivalence, stale/cancelled result rejection, decision replay, approval/export guards, durable review evidence, explicit session application, lightweight status events and millimeter-source instructions. A concurrent two-store test commits exactly one of two edits against the same base revision and records exactly one geometry-change event. See [test_edge_sessions.py](../../tests/test_edge_sessions.py).

The first integrated analysis test exposed duplicate `source_revision` keyword assembly when publishing a result. That defect was fixed, and all session tests were rerun successfully. No tests were removed or weakened. One upstream Starlette/httpx TestClient deprecation warning remains.

The final integrated Python suite passed **152 tests in 23.61 seconds**, including the 87-test preserved baseline, 32 session tests, remote-worker tests and six additional CAD exchange tests. This includes the optional STEP tests in the prepared instance. The remote tests exercise real loopback HTTP, request/digest validation, timeouts, bounded load and local fallback; their device is the current Linux x86_64 host. CAD exchange cases check millimeter-to-meter conversion, real handle preservation, explicit unitless input, contradictions, assigned-line joining and export/reimport consistency. Session additions check lightweight status events and reviewed millimeter-source modification instructions.

The final production TypeScript/Vite build passed. Both preserved Chromium workflows passed against the running Edge application, with no JavaScript exceptions. The original smoke test exercised inefficient, congested and sealed-bulkhead scenarios plus actual JSON/DXF/CSV/report downloads. The v2 regression exercised all eight scenarios, distinct candidate selection, point measurement, what-if recomputation and STEP download/reimport with eight solids. These are browser/API checks, not native Autodesk or physical-device verification.

The final [Edge Chromium workflow](../../tests/browser_edge_workflow.py) also passed with no JavaScript exceptions. It verified approved JSON download, stale approval rejection, preview protection against automatic source sync, live delta analysis, real HTTP remote processing and local fallback, millimeter DXF import with actual entity handles, shared-session attachment and external revision/analysis monitoring. The main session reached revision 4. The attachment fixture was an API-created session marked `source_adapter=autocad`; its source edits and externally submitted analysis used the backend API. This verifies the browser/session contract without executing the C# connector or AutoCAD. A [session-attachment screenshot](/workspace/pipeforge-artifacts/edge/native-session-attachment.png) is retained in the prepared instance.

The canonical model and all engineering metadata dimensions use meters. DXF source units and the native connector's supported `INSUNITS` scale are retained as a checked `coordinate_transform`. Reviewed JSON includes original/proposed `source_coordinate_instructions` in the source units as well as its canonical meter model. The legacy meter-only import/export contract is preserved. No automatic origin, orientation or solid-to-system interpretation is inferred.

The native `PFCOMPANION` command opens the shared session URL. `PFREFRESH` checks synchronized native geometry, session identity, units and revision before retrieving browser recommendations, proposals and decisions. It refuses dirty native edits and never applies a remote model to the drawing. These mechanisms have been inspected at source level; actual command execution remains part of the unverified Windows smoke test.

All 19 pinned CPU-worker dependencies were also downloaded successfully for CPython 3.12 Linux ARM64 compatible wheel tags without executing them. The NumPy/SciPy wheel tags require glibc 2.27 or newer; this is a distribution prerequisite, not proof of board installation or runtime compatibility. The [wheel observations](../../deployment/edge/arm64-wheel-observations.json) distinguish this artifact check from actual IQ-9075 execution. Native C# source parsing, project XML parsing and metadata schema validation succeeded; compilation and Autodesk execution remain unverified.

The recorded same-host Linux x86_64 loopback benchmark measured local versus remote total latency at approximately **4.14/17.95 ms** for inefficient-route analysis, **40.35/102.01 ms** for its optimization, and **120.80/176.84 ms** for congested optimization at 1 m resolution. These are observations on this host, not a remote-device benchmark. Offloading was slower for these cases; keeping work local is supported. Remote totals include deterministic local verification. Network/HTTP/queue overhead is measured together; separate one-way transfer times cannot be resolved by this request/response protocol. See the [recorded observations](../../deployment/edge/benchmark-observations.json).

The separate [40-pipe session benchmark](../../deployment/edge/session-benchmark-observations.json) checked full-analysis equivalence, incremental reuse and actual HTTP payloads over three runs. After one localized edit, full analysis took a median **1250.54 ms**, while incremental analysis took **30.63 ms**, reusing 39 routes and recomputing one. Warm unchanged analysis took 0.45 ms; the SQLite geometry patch took a separate 7.44 ms. These analysis timers exclude SQLite capture/publication. The initial full request was 20,274 bytes and the one-edit delta 866 bytes; both responses were 30,097 bytes. This disjoint sparse fixture demonstrates a favorable cache case, not a general latency guarantee. Remote totals remained slower because full local verification still ran; no Qualcomm result is inferred.
