## Bounded coordinated optimization

The small-network prioritized/reservation workflow is preserved. Above the local span threshold, a large-neighborhood controller builds a weighted interaction graph from explicit shared nodes and conservative finite-envelope spatial overlap. It prioritizes measured violations and geometric detours, packs primary groups of approximately eight selected spans, explores alternative orders and temporarily releases only unplanned permitted routes in a group. Neighboring components at group boundaries stay fixed. Node moves require designer permission and participation of every incident span in that subproblem.

Each accepted local change updates a private incumbent used by subsequent groups. An intermediate repair can be retained internally only when its independently measured violation rank improves; an invalid internal repair is never published as a proposal. Conflict-driven expanded neighborhoods can revisit unresolved interactions. Every complete returned candidate passes the independent whole-network validator against the immutable source, including unselected systems, all retained components and obstacles.

This is a bounded heuristic, not a global multi-commodity optimum. A selected span can be considered using an independently justified unchanged-straight reuse or geometry-cache hit. **Forty selected/considered spans do not mean forty A* searches or forty changed spans.** Reports separate selected count, considered IDs, changed IDs, local solves, actual new expanded states, peak grid nodes, cache hits and evaluated candidates.

Local routing uses influence windows, conservative obstacle broadphase and bounded spatial/resolution stages. It first tests a direct fixed-endpoint leg where applicable, then uses the existing finite-grid router. If a window or resolution cannot establish a route, bounded fallback stages may explore a broader/coarser region. A budgeted failure is not permission to omit surrounding geometry.

The canonical schema still bounds a snapshot to 128 spans, 256 nodes and its existing geometry budgets. Actual industrial evidence reaches **40 selected connected runs**; support for the schema maximum is not a claim that 128-run industrial optimization has been verified. Search remains capped at 64 candidate evaluations and 120 seconds. Local grid estimates are checked against a 50,000-node industrial budget before allocation. Route cache, per-search geometry cache and physical-fitting cache have explicit count/byte limits. Cache reuse stores geometry, never an engineering PASS verdict.

Progress reports actual phases, neighborhood/evaluation counts, active IDs, local solves and search counters. Cancellation and time limits are cooperative; complete independent validation remains an acceptance gate. Termination distinguishes designer cancellation, time-budget expiry, evaluation limit, blocked metadata and completed bounded search. `NO FEASIBLE ROUTE FOUND` means no accepted candidate was found within that search; it is not a proof about all continuous-space configurations. A timeout preserves the original unless a separately verified acceptable proposal was already established; cancellation discards a proposal.

## Physical components and independent validation

Valves, tees, flanges, reducers, elbow nodes and supports have distinct physical representations. Supplied body length/radius and WCS axis yield conservative finite cylinder bounds. Explicit conservative AABBs or capsule envelopes can carry their source; an undersized contradictory override cannot hide known dimensions. Missing length, axis, approval or complete geometry remains explicit uncertainty. Legacy sphere-only component metadata retains its original limited interpretation.

Physical checks include component-to-pipe, component-to-component, support contact, structure, other systems, fitting sweeps and self-interference. Connected parts have only bounded local attachment exemptions; an entire incident span or hanger is not erased from the environment. Flange installation/tool clearance uses the supplied component requirement, separately from the transcribed 50.8 mm shock-clearance rule. Explicit reducer permission, incident nominal/outer compatibility, fixed boundaries, source IDs, dimensions, systems and engineering constraints are independently preserved.

Original and proposed layouts use the same applicable checks. Results distinguish resolved, persistent and introduced measured findings. Missing metadata is UNVERIFIED, not a demonstration default. Industrial geometric acceptance does not establish an approved catalog, pressure/material specification, complete bolting/tool motion, support anchorage, installation sequence or fabrication release.

The existing versioned Fincantieri challenge transcription remains the standards source. Shock clearance, walkway headroom, valve access, bend radii/net straights, manufacturing piece lengths/bend counts/weld spacing, flow-directed ship-axis drainage and unresolved structural-penetration wording remain represented. No new component approximation is presented as an additional official standard. See [the existing engineering interpretation](V5_0.md#independent-engineering-validation) for exact requirements and authority limitations.

## Interactive environment changes

Review obstacles can be selected, added, moved and removed in the companion. A new hypothetical obstacle is explicitly marked as a designer-review simulation. Existing CAD-source geometry, protected equipment and ship structure cannot be moved or deleted through review controls. Source drawings and their native entities remain unchanged.

An edit produces a new environment revision and source digest, identifies affected finite pipe/fitting envelopes from the old/new volume, recomputes complete-network collisions/clearances, and offers affected-span coordinated optimization with all supplied context retained. Editing invalidates a prior approval/export. Moving a wall away or removing a review obstacle triggers fresh analysis rather than reusing an old validation verdict. Edit history, count and retained byte budgets prevent unbounded session growth.

Fresh source inspection has a separate analysis-session identity. Reloading an original example after hypothetical edits can start a fresh review baseline without being permanently rejected by a different session's environment revision. Results/approvals from an earlier edited session remain stale; a fresh inspection does not authorize an old proposal. Session-bound browser source digests can therefore differ from the normalized standalone fixture digest used by the CLI benchmark.

Collision detection and a hypothetical editable box are engineering review tools, not authority to remove actual ship structure. Maintain source provenance and designer permissions. A sealed review environment must produce its measured blocked/timeout outcome instead of a fabricated detour.
