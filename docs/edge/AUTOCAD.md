# Regular AutoCAD native connector

The connector is an actual C# AutoCAD .NET project in `connectors/autocad/PipeForge.AutoCAD`. It reads supported native entities, associates them with explicit engineering metadata and submits work to the Edge API. The browser's CAD file exchange remains a separate integration path.

**Verification boundary:** this Linux environment has no `dotnet`, C# compiler, Autodesk managed reference assemblies or running AutoCAD. The project, metadata JSON and API contract have been inspected; native compilation and execution remain unverified. The Windows checks below are required before describing the native integration as demonstrated. No latency number from a browser or HTTP test measures native AutoCAD latency.

## Host and build

The requested product is regular AutoCAD. Its release remains unknown: use `ABOUT` on the workstation. This project targets **AutoCAD 2025/2026, Windows x64, .NET 8**, using `AcCoreMgd.dll`, `AcDbMgd.dll` and `AcMgd.dll` from an installed host. Build against the exact installed release. No Autodesk binaries are shipped, downloaded, or copied into the output (`Private=false`). AutoCAD 2024 and earlier use .NET Framework and need a separate target and compatibility work; this DLL cannot be assumed to load there. AutoCAD LT, Mac, Civil 3D/Plant 3D semantic objects and Autodesk cloud authentication are not supported by this adapter.

Install the .NET 8 SDK on the Windows workstation through Microsoft's supported installer, then from the repository root:

```powershell
dotnet build .\connectors\autocad\PipeForge.AutoCAD\PipeForge.AutoCAD.csproj `
  -c Release '-p:AutoCADDir=C:\Program Files\Autodesk\AutoCAD 2025'
```

For AutoCAD 2026 change `AutoCADDir` to that installation. Expected output is `connectors\autocad\PipeForge.AutoCAD\bin\Release\net8.0-windows\PipeForge.AutoCAD.dll`. Build errors about missing Autodesk references require the real installed managed DLLs, not placeholder assemblies. Follow the organization's normal AutoCAD trusted-path/signing policy for this DLL; do not disable `SECURELOAD` or signature checks.

Start the Python main application using the repository launch instructions, default port `8000`. `PFCONNECT` takes this main application's base URL; `PFCOMPANION` opens the browser on the same URL. The optional remote optimization worker on port `8010` is a separate service and is not a native connection/companion endpoint. If AutoCAD runs on another workstation, `127.0.0.1` refers to that workstation, not this cloud instance. Use a reachable private or authenticated forwarded server URL, and keep the prototype API on a trusted development connection. `NETLOAD` the DLL in AutoCAD, then enter `PFHELP`.

## Explicit model metadata and mapping

Copy `connectors/autocad/model.example.json` to a local file. It is a template, not a real DWG binding: replace both `REPLACE_WITH_...` values with hexadecimal entity handles from the source drawing (`LIST` can report the selected entity handle). A mapping supplied by the adapter is an actual native handle. File-exchange imports without this explicit binding do not establish a native handle.

The envelope is:

```json
{
  "model": { "id": "project-id", "name": "Name", "units": "m", "bounds": {"min": [0,0,0], "max": [12,8,5]}, "pipes": [], "obstacles": [] },
  "object_map": { "P-101": "1A2B", "ENGINE": "1A2C" }
}
```

Use a complete, valid PipeForge model; the tiny envelope above only illustrates the schema. An existing PipeForge JSON model/export can supply `model`; review every system, editable flag, diameter, service category, slope, flow direction, hydraulic property, bounds and fitting entry. All engineering dimensions in metadata use **meters**, regardless of DWG units. Preserve the source world coordinate system and explicitly set bounds to cover the working volume. No pipe system, equipment function, nozzle purpose, approval, diameter or bend radius is inferred from a layer name or shape. Fitting definitions and approval flags are provided metadata and remain subject to independent review.

Each native pipe maps to one **open, simple `Polyline3d`** representing its centerline. The plugin reads its actual vertices. Closed, fit/spline 3D polylines, 2D/LW polylines, arbitrary pipe solids and multiple fragmented entities per engineering object are rejected. An obstacle maps to one supported entity with nondegenerate `GeometricExtents`; the world-axis-aligned extents conservatively bound it. Rotated equipment is represented by its enclosing axis-aligned box; this is not an exact solid intersection engine. **Live `BlockReference` and xref bindings are rejected** because definition-child changes are not tracked; classify/extract supported geometry explicitly before connecting. Their presence as unbound source entities makes extraction coverage incomplete. All initial handles must resolve to live objects in the connected drawing's database. Lookup errors fail connection/capture and are never interpreted as deletion. Later confirmed erasures can remove mapped objects from the active model. Reopening the same drawing generally preserves handles, but copying/erasing/replacing objects can invalidate them; reconnect and check the mapping.

The server normalizes object mappings to arrays. This adapter accepts singleton arrays as well as single strings and canonicalizes hexadecimal handles before comparison, so padded/whitespace variants cannot bypass duplicate checks or event matching. It rejects multiple handles for one object. `PFMAP` selects a native entity and assigns it to an ID **already present in the supplied metadata**. It changes the session-local binding only; update the local metadata file to preserve it across reconnections. Unbound entities are retained as explicit unresolved source records; they are never inferred to be pipes or silently converted into engineering obstacles. Add explicit metadata and bindings, or choose an explicitly scoped drawing, before native approval/export. Unmapped objects already in `model` are static metadata geometry and do not become live native objects.

The connector scans at most **10,000 modelspace entities** in a UI-thread read transaction; a larger scope fails closed. It sends `extraction_coverage` on session creation and deltas: schema version, adapter/scope, source generation, mapped/unmapped counts, unresolved handles with actual entity type/layer/reason, explicit ignore records and unbound metadata IDs. Coverage is `incomplete` for unresolved source entities, `unverified` for unbound static metadata, and `complete` only when this declared modelspace scope has no unresolved/static items. It does not claim to interpret the entire drawing database. No native ignore/classification editor exists yet. Native approval/export require complete synchronized coverage; diagnostic analysis can still show limitations. Coverage persists in the session and reviewed assurance instead of becoming a prose assumption.

For DXF fallback exchange, closed and curve/spline-fit 3D polylines are rejected before chaining so no closing edge or fitted curve is dropped. Unsupported assigned centerlines also fail explicitly. Other source entities remain unresolved with handles/type/layer; static metadata obstacles remain qualified. Exported `ORIGINAL_` comparison routes are ignored only when their explicit PIPEFORGE identity and size metadata match; an arbitrary layer prefix does not suppress source coverage. Source obstacle-face handles are retained alongside pipe handles.

`INSUNITS` must explicitly identify inches (`1`), international feet (`2`), millimeters (`4`), centimeters (`5`), meters (`6`) or kilometers (`7`). Coordinates and obstacle bounds are scaled to canonical meters; preview coordinates are scaled back into drawing units. Unitless (`0`) and other unit types fail without guessing. Changing `INSUNITS` during a session invalidates results and requires reconnecting; checks run on idle, before preview/decision and at export publication, even if no mapped entity changed. The adapter reads WCS coordinates; it does not translate origins or reinterpret the current UCS.

Session creation also sends the explicit `coordinate_transform` with `source_units` (`m`, `mm`, `cm`, `in`, `ft` or `km`) and the actual `meters_per_unit` derived from `INSUNITS`. The server model remains in meters. Reviewed JSON packages expose this transform under `edge_approval.coordinate_transform` and provide `source_coordinate_instructions`, so original/proposed centerlines can be interpreted in the source CAD units without guessing. This does not create or update drawing entities; preview continues to use the same inverse scale.

## Commands and decision boundary

| Command | Behavior |
|---|---|
| `PFCONNECT` | Prompt for metadata envelope and Edge server URL; capture mapped source geometry; create a revisioned Edge session. Default URL is `http://127.0.0.1:8000`. At least one explicit mapping is required. |
| `PFMAP` | Prompt for an existing engineering ID and select its native source entity. Validate the entity type and send a binding/geometry delta. |
| `PFCOMPANION` | Print and open the browser URL with `?edge_session=<id>` for this actual native session. If browser launch is blocked, open the printed URL manually. |
| `PFREFRESH` | Recapture synchronized native geometry and fetch current-revision browser proposals and decision status for this session. Refuse pending local edits/in-flight synchronization and discard replies that become stale. Never adopt the remote model or change CAD entities. |
| `PFANALYZE` | Recapture current mapped geometry and submit an asynchronous analysis job. |
| `PFOPTIMIZE` | Recapture and submit asynchronous balanced optimization (`resolution=0.5 m`, `clearance=0.1 m`). |
| `PFLIVEON` / `PFLIVEOFF` | Enable/disable automatic lightweight analysis after debounced synchronization. Default is off; at most one live-analysis job runs, and newer edits coalesce into another analysis. Geometry streaming continues when off. |
| `PFHIGHLIGHT` | Highlight mapped source entities for an entered ID or the current recommendation list. Unknown/unbound IDs cannot highlight native objects. |
| `PFPREVIEW` | Choose a numbered current proposal; draw changed centerlines as cyan transient graphics. Fresh proposals with incomplete source coverage carry an explicit UNVERIFIED diagnostic warning. No database construction entities are created. |
| `PFAPPROVE` / `PFREJECT` | Prompt for engineer, comment and explicit `Yes`; record the selected proposal decision for its source revision. This changes only decision state on the server. |
| `PFEXPORT` | Download JSON, DXF, CSV or report for the current approved proposal to a **new** local file. Existing files are never overwritten. The server independently checks revision and approval. |
| `PFCLEAR` | Remove transient preview and highlights. |
| `PFDISCONNECT` | Unsubscribe database events, cancel pending HTTP work, remove visuals and dispose the connection. Closing the drawing also disposes it. |

There is no native “apply” command. Approval enables export and records an engineering review decision; it does not certify the design, update the DWG or create approved construction geometry. Review the exported proposal and implement any source drawing change separately through the engineering process. Original source entities are never opened `ForWrite`. The plugin does not save or overwrite the DWG.

To review the native session in the browser, run `PFCOMPANION` after `PFCONNECT`. The URL attaches the existing session; creating a separate browser session does not create a bridge to this DWG. Native sessions identify `source_adapter=autocad`, so the attached browser does not synchronize its workspace geometry into the native source session. Analyze, optimize and record the designer decision in the companion. Back in AutoCAD, wait for native edits to synchronize, run `PFREFRESH`, then `PFPREVIEW` to choose a current proposal and `PFEXPORT` for an approved artifact. Browser approval status is retrieved explicitly; it is not guessed from an older native result.

`PFREFRESH` first refuses pending local changes or an outgoing native delta, then recaptures all mapped entities in a UI-thread read transaction. If that capture discovers an event that was missed, its delta advances the source revision and invalidates older browser proposals. The GET response must match the expected session, native source adapter and current revision; a second UI-thread check verifies epoch, units, job generation and absence of pending synchronization. Only recommendations and proposals for that source revision are retained. A changed remote revision requires reconnecting; remote drawing geometry is never adopted as native truth. This bridge does not make unsupported entity types or unmapped geometry live.

## Live synchronization and thread discipline

Database `ObjectModified`, `ObjectAppended` and `ObjectErased` callbacks capture identifiers only. Child `PolylineVertex3d` changes capture the owning centerline handle. Unbound entity edits also invalidate the local result epoch immediately and mark extraction coverage dirty. The plugin waits **400 ms** after the latest source edit and captures mapped geometry plus modelspace coverage on `Application.Idle`, while the active editor is quiescent, using a document lock and read-only transaction. It sends `upsert_pipes`, `remove_pipe_ids`, `upsert_obstacles`, `remove_obstacle_ids`, explicit mappings and `extraction_coverage`. A coverage source-generation increment changes the backend revision even if an unknown object's handle is unchanged, invalidating browser approvals after an unknown-solid edit. Native approval/export remain blocked while coverage is dirty or incomplete; fresh diagnostic previews and rejection remain available once synchronized. A confirmed mapped erase removes the model object; an undo/un-erase can restore it from retained metadata. No complete engineering model is resent for each edit.

`HttpClient` requests and job polling are asynchronous with cancellation, per-request timeouts and a three-minute polling limit. There is no `.Wait()`, `.Result`, database traversal from a worker or HTTP request inside a database event. Revisioned writes are serialized. Replies enter a UI queue drained by `Application.Idle`. Source edits invalidate pending result/preview epochs, so a reply for an older drawing state is discarded. The server also enforces source revisions. Export downloads are staged off the UI thread and published to a new file only after a final UI-thread epoch/unit/revision/approval check. Capture/transport failure pauses synchronization and prints a reason; correct it and reconnect instead of continuing with a false “live” state.

Delta requests set `compact=true`, so acknowledgments contain revisions, affected IDs and mappings without echoing the entire drawing. Live streaming synchronizes geometry. `PFLIVEON` optionally schedules analysis after successful synchronization, with at most one automatic analysis in flight and newer updates coalesced; it defaults off. Explicit optimization temporarily takes precedence over automatic analysis, and later source edits invalidate the proposal. Automatic optimization and automatic source application are not enabled. The browser can supply richer diagnostics while connected to the same backend; source handles only refer to the native session that supplied them.

## Windows acceptance checklist (pending)

Use a disposable drawing, keep the original project drawing closed, and retain build/host version evidence.

1. Verify `ABOUT` reports AutoCAD 2025/2026; build against that release, `NETLOAD`, and confirm `PFHELP` works. Confirm an unsupported host fails clearly instead of claiming readiness.
2. In a new drawing with `INSUNITS=6`, draw an open 3D polyline using the example points, and a 3D box spanning `(4,4,0.2)` to `(6,6,2)`. Obtain their actual handles; replace template placeholders and review the supplied engineering metadata.
3. `PFCONNECT` to the running Edge server. Confirm the initial model centerline coordinates, mappings and coverage match the DWG. Repeat in an equivalent millimeter drawing (`INSUNITS=4`, drawing coordinates multiplied by 1000): backend coordinates must match in meters. Confirm `INSUNITS=0` is rejected. Confirm wrong-drawing/nonexistent/erased initial handles fail without creating a reduced model; padded equivalent handles canonicalize and duplicate aliases are rejected. Confirm a live block/xref binding fails explicitly.
4. `PFANALYZE`, then `PFHIGHLIGHT`. Confirm identified native objects highlight and the AutoCAD UI remains usable while the HTTP job runs. `PFCLEAR` must remove highlights.
5. `PFOPTIMIZE`, `PFPREVIEW 1`. Confirm cyan centerlines are temporary, the original polyline is unchanged and entity count is unchanged. Verify the current proposal and independent validation in the Edge session.
6. Grip-edit a mapped centerline vertex. After it becomes idle, confirm one debounced delta and compact revision update. `PFLIVEON`, edit repeatedly, and confirm one automatic analysis is in flight with coalesced follow-up work; `PFLIVEOFF` must stop automatic analysis while geometry deltas continue. Modify/delete a mapped obstacle and confirm the affected analysis changes. Undo the erase and confirm model restoration. After obtaining an approval, append an unbound solid: native review/export must block immediately and the stable coverage delta must invalidate the browser approval. Modify the same solid again: its unchanged handle must still advance source generation/revision. Delete it and confirm coverage is rescanned; add any required metadata/binding deliberately before re-analysis and review.
7. Start optimization, edit before its reply, and verify the older reply is discarded. Confirm a stale proposal cannot be previewed, approved or exported. Simulate a network failure and confirm synchronization pauses without freezing AutoCAD or silently showing a current result.
8. Optimize the current state, preview and `PFAPPROVE` with an engineer ID and explicit `Yes`; `PFEXPORT` to a new JSON/DXF file. Verify revision/approval gating, units and unchanged original geometry. Reject a separate proposal and verify export is refused. Verify existing output paths are refused.
9. `PFDISCONNECT`, reconnect, then close the document during a job. Confirm events do not duplicate, tasks cancel and overlays disappear. Check original DWG timestamps/hashes or saved entity geometry before and after the connector-only workflow.
10. `PFCOMPANION` must open/print a URL containing the exact native session ID. In the attached browser, optimize and approve a current proposal; in AutoCAD run `PFREFRESH`, select it with `PFPREVIEW`, and confirm `PFEXPORT` recognizes the server decision. Verify a different session's proposal is never adopted. Repeat refresh while a mapped edit is dirty, while its delta is in flight, after changing units, and while editing during the GET response: each case must refuse or discard stale data. Confirm the bridge never writes source geometry.

Record native timings only after this sequence passes. A successful backend test suite cannot replace these host checks.
