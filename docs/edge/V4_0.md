## Standards authority and interpretation

The versioned profile is `fincantieri-track2-user-transcription-v1`. Its numerical requirements come from the user's PipeForge Edge 4.0 challenge transcription. The original organizer PDFs have not been independently reviewed in this environment. Source references and verification state remain part of the profile rather than being replaced with a claim of official approval.

The profile keeps hard constraints separate from preferences. Shock clearance is 50.8 mm measured from occupied pipe and fitting envelopes. A vertical hanger distance above 381 mm and valve stem heights outside the stated ranges are preferences, while the stated horizontal hanger maximum is 50.8 mm. Missing support, installation or access geometry remains UNVERIFIED. The conflicting penetration separation wording, “2 inch / 50 mm,” remains unresolved until an authoritative unit/value is supplied. An uncovered nominal diameter does not receive an interpolated bend rule.

Drainage checks require explicit ship directions; world X/Y are not silently treated as fore-and-aft/athwartship. The required ratios are 1:25 and 1:100 respectively, evaluated along individual flow-direction segments. Endpoint drop alone cannot establish drainage functionality.

## Data and review contract

The connected schema uses global WCS coordinates in millimeters and explicit nodes/spans. Equipment ports, valves, tees, junctions, fittings, endpoints and system boundaries have stable engineering IDs. Source handles, nested instance paths, system identifiers, dimensions, fixed status and movement constraints remain attached to the model.

Geometric proximity proposes a connection; it does not establish one. Ambiguous candidates remain unresolved until the designer confirms the actual topology. Equipment and required connections stay fixed. A valve may move only within a declared movement region or permitted positions. Mandatory compartment traversal and surrounding systems remain constraints of the affected network.

Results retain original and proposed networks, source revision/digest, changed span IDs, measured before/after metrics, independent validation and unresolved issues. A source edit invalidates an older result. Preview and instruction export do not edit source CAD entities. Native source edits require their own deliberate designer action.

Every check returns PASS, FAIL, UNVERIFIED or NOT_APPLICABLE with component IDs and numerical evidence where available. Geometric feasibility, engineering constraint feasibility and manufacturing verification are separate result fields. Missing geometry or catalog information cannot establish complete compliance.

## Coordinated search and physical scope

The connected engine reuses the team's existing bounded route search. It considers editable spans and declared movable-node alternatives, carries the geometry of other spans into each search, then validates the complete candidate network before acceptance. Shared-port contact exemptions are locally bounded; the remote parts of incident pipes remain obstacles. Required compartment waypoints are included in the search and checked afterward.

The network objective reports total length, direction changes/fitting requirements, elevation change, modification cost and preference warnings. A hard validation failure disqualifies a candidate rather than becoming a cost that a shorter route can outweigh. Unchanged sections retain their original geometry. The search is bounded, deterministic and cooperative; **NO IMPROVEMENT FOUND** means no acceptable improvement was established within the search performed, not a mathematical proof of global optimality or infeasibility.

Physical fitting checks use supplied catalog dimensions and swept tangent-bend envelopes. Synthetic scenarios declare provisional catalog entries explicitly. These analytic envelopes do not constitute detailed manufacturer solids, installation simulation, pipe stress analysis, support design or commercial component approval. A collision-free centerline cannot establish physical fitting clearance by itself.

## Companion and output package

Both the team's `scripts/run_web.py` service and the preserved FastAPI service expose `/connected`. The connected companion loads synthetic scenarios, reconstructs a network from an authorized imported CAD inspection, displays unresolved connection decisions, edits explicit JSON, runs network validation and submits asynchronous optimization jobs. The viewer compares original/proposed geometry and exposes exact component coordinates.

Instruction export requires an explicit review decision and a server-issued result token matching the current source digest/revision. The server recomputes validation rather than trusting a supplied PASS result. Download names are allowlisted; exporting instructions does not invoke native source replacement.

The package contains `instructions.json`, `instructions.md`, `components.xlsx`, `components.csv`, `network-preview.dxf` and `network-result.json`. Instructions retain source CAD IDs, system IDs, fixed ports, original/proposed global coordinates, dimensions, fitting provenance, manufacturing pieces, metrics and unresolved checks. The Excel workbook is a real `.xlsx` file with Components, Coordinates, Manufacturing, Checks and Metadata sheets; unknown values are labeled rather than fabricated. JSON/XLSX/CSV/DXF coordinates and identities are read back and checked against the selected global-WCS model with a 0.000001 mm tolerance. The DXF is a scaled centerline review overlay, not a replacement set of manufactured solids.

Manufacturing is assessed per piece, with proposed segmentation at a maximum 6,096 mm and three bends per piece. Proposed cuts avoid bend interiors and retain supplied existing welds. Lengths/stations are calculated from geometry; supplied gaps, overlaps or false coordinates fail validation. Missing weld information, catalog approval, fabrication method or applicable planarity tolerance remain UNVERIFIED. Proposed piece boundaries are planning instructions, not evidence that a fabrication shop has approved the process.

## Remaining integration boundaries

- Engineering truth still requires reviewed system/port metadata. A CAD solid or a pair of nearby endpoints cannot automatically supply valve, tee, equipment or nominal-size semantics. Ambiguous connections require explicit decisions.
- Full geometry coverage must be declared and reviewed. Unsupported/omitted objects and unknown physical catalog data retain UNVERIFIED outcomes; a synthetic fixture's complete declaration is not a complete ship survey.
- Fitting envelopes are conservative analytic approximations with provenance. Approved manufacturer catalogs, actual fitting insertion, installation sequencing, supports/stress and shipyard fabrication approval remain outside the verified scope.
- The penetration source's conflicting “2 inch / 50 mm” wording requires an authoritative resolution. The implementation does not silently choose one conversion.
- Coordinated routing is bounded heuristic search over supplied permitted movement/geometry. Cancellation is cooperative, and bounded-search failure is not a proof that every conceivable route is impossible.
- Native commands require the Windows host checklist. This sharing snapshot includes plugin source only; build it before loading the commands. Native source-solid replacement, NETLOAD/event handling/Undo and physical device performance have not been exercised here.
- Local/remote processing from Edge 3.2 is preserved. Current connected-network timings measure local CPU execution; they do not establish a new connected-network remote protocol or device speed advantage.
